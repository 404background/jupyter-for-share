# jupyter-for-share

Windows PC を JupyterLab サーバーにして、LAN 内の別の PC からブラウザで使うためのセットアップスクリプトです。

- **ユーザー名を指定するだけ**でユーザーごとの環境を作れます (`jfs.cmd add alice`)。ポートは空いている番号が自動 (ランダム) で割り当てられます
- 環境は**このリポジトリの `user` フォルダの中にユーザーごとに作られ**、各環境は**自分のフォルダの中だけ**読み書きできます
- ノートブック・**ターミナル (PowerShell)** の両方が使えます
- パッケージはユーザーごとの **Python 仮想環境 (venv)** に `pip install` で自由に入れられます。`git clone` も使えます
- **リソースモニター**専用のポート (既定 8000) で、サーバーの CPU・メモリ・GPU の使用率をブラウザで確認できます
- **コンピューター名やドメイン名**でアクセスできます (例: `http://jupyter-pc:23456/`)
- Docker は使いません。Windows 標準の機能 (ローカルアカウント・NTFS アクセス権・タスクスケジューラ・ファイアウォール) で構成します

## 仕組み

```
jupyter-for-share\                    ← このリポジトリ (管理者だけが読み書きできるように設定されます)
├─ setup.cmd / jfs.cmd               ← セットアップ / 管理コマンド
├─ servers.json                      ← 設定 (各ユーザーのポート・トークン)
├─ monitor\                          ← リソースモニター (ポート 8000 / アカウント jfsmon で実行)
└─ user\
    ├─ alice\                        ← ユーザー alice の環境 (ポート例 23456 / アカウント jfs-alice で実行)
    │   ├─ work\                     ← JupyterLab のルート。ノートブックや git clone したものはここ
    │   │   └─ README.md             ← 本人向けの説明 (環境とリソースモニターのアドレス)
    │   ├─ venv\                     ← パッケージを入れる venv (カーネル・ターミナルの python/pip)
    │   ├─ .logs\                    ← server.log (サーバーのログ) と commands.log (本人が実行したコマンド)
    │   └─ .server\                  ← JupyterLab 本体・設定 (隠しフォルダ)
    └─ bob\                          ← ユーザー bob の環境 (別のポート / アカウント jfs-bob)
```

- 各環境は専用の Windows ローカルアカウント (`jfs-<ユーザー名>`) として動きます。JupyterLab だけでなく、
  ノートブックのコードやターミナルもこのアカウントの権限で動くため、**NTFS のアクセス権で読み書きできる範囲が制限**されます。
  (JupyterLab の設定だけで制限すると、ターミナルやコードからは PC 中のファイルが見えてしまうため、この方式にしています)
- サーバー実行用アカウントは画面からのサインイン・リモートデスクトップ・ネットワーク共有へのログオンが禁止され、サインイン画面にも表示されません。
- 全ユーザーのサーバーは、`jfs.cmd start` を実行したウィンドウ (**サーバー管理ウィンドウ、1 つだけ**) の中で動きます。
  ウィンドウには全員のサーバーのログと実行したコマンドが `[ユーザー名]` 付きでリアルタイムに表示され、
  **ウィンドウを閉じると全員のサーバーが停止します** (詳しくは「サーバー管理ウィンドウとログ」)。
- リポジトリはどのドライブ・フォルダに置いても構いません (例: `E:\jupyter-for-share`)。ユーザー環境はその中の `user` フォルダに作られ、
  他のフォルダへのアクセス禁止もリポジトリの場所に合わせて設定されます。ドライブは NTFS である必要があります。
- リポジトリのフォルダ (スクリプトや `servers.json`) はサーバー実行用アカウントからは読み書きできません。

## 必要なもの

- Windows 10 / 11 (64bit)。サーバーとして使う PC の管理者権限
- インターネット接続 (Python・Git・JupyterLab のダウンロード用)
- 接続する PC と同じ LAN
- (GPU の使用率表示) NVIDIA の GPU はドライバ付属の `nvidia-smi` で詳しく表示します。その他の GPU も Windows の情報から使用率を表示します

## セットアップ (サーバー PC で 1 回だけ)

1. このリポジトリをサーバー PC にクローンします。
   ユーザー環境はこのフォルダの中に作られるので、空き容量があり、パスに日本語や空白が無い場所 (例: `C:\jupyter-for-share`) をおすすめします。

   ```bat
   cd C:\
   git clone https://github.com/404background/jupyter-for-share.git
   cd jupyter-for-share
   ```

   (Git が無い場合は ZIP をダウンロードして展開しても構いません)

2. `setup.cmd` をダブルクリック (またはコマンドプロンプトで実行) します。管理者権限の確認が出たら「はい」を選びます。

   ```bat
   setup.cmd
   rem オプションの例: ドメイン名を設定し、スリープを無効にする
   setup.cmd -Domain jupyter.home.arpa -DisableSleep
   ```

setup で行うこと:

| 内容 | 詳細 |
| --- | --- |
| 最新版への更新 | 最初に `git pull` でこのリポジトリを最新にします (git でクローンした場合。失敗しても今のファイルで続行) |
| Python / Git のインストール | winget で全ユーザー向けにインストール (インストール済みならスキップ) |
| 設定ファイル作成 | `servers.json` (`servers.example.json` をコピー) |
| サーバー実行用グループ | `jupyter-for-share-users` を作成し、ログオン権限を設定 |
| フォルダのアクセス権 | このリポジトリ・`user` フォルダ・`C:\ProgramData\jupyter` を管理者以外が変更できないようにする |
| 他フォルダへのアクセス禁止 | 後述の「アクセス制限」。このウィンドウで実行し、終わるまで進み具合を表示します (`-SkipProtect` で省略可) |
| リソースモニター | 設置のみ。`jfs.cmd start` のサーバー管理ウィンドウの中で動きます (ポート 8000。`-MonitorPort 9000` で変更、`-SkipMonitor` で省略可) |

### 更新するとき

`setup.cmd` をもう一度実行すると、`git pull` で最新版を取り込んでからセットアップをやり直します。
ユーザー環境やトークンはそのまま残ります (各ユーザーの `README.md` も最新の内容に更新されます)。

## ユーザー環境を作る・管理する

`jfs.cmd` を使います (管理者権限が必要です。通常のコマンドプロンプトから実行すると UAC の確認が出ます)。
コマンドプロンプトではこのフォルダで `jfs.cmd ...`、PowerShell では `.\jfs.cmd ...` と入力します。

```bat
rem 使い方の一覧 (jfs.cmd -h、jfs.cmd --help、jfs.cmd /? でも同じ)
jfs.cmd help
rem コマンドごとの詳しい説明
jfs.cmd help add
```

```bat
rem ユーザー alice の環境を作成 (フォルダ: user\alice、ポートは自動)
jfs.cmd add alice
rem サーバーを起動 (このウィンドウがサーバー管理ウィンドウになり、ログが流れ続けます)
jfs.cmd start
```

作成が終わると接続用 URL (トークン付き) が表示されるので、本人に伝えてください。
ユーザー名は半角英数字とハイフン (16 文字以内) で、大文字は小文字に変換されます。

| コマンド | 内容 |
| --- | --- |
| `jfs.cmd list` | ユーザー環境とリソースモニターの一覧・状態・ポート |
| `jfs.cmd url [ユーザー名]` | 接続用 URL を表示 (省略で全員分 + リソースモニター) |
| `jfs.cmd start [ユーザー名]` | サーバーを起動 (省略すると全員)。実行したウィンドウがサーバー管理ウィンドウになり (新しいウィンドウは開かない)、閉じると全員停止 |
| `jfs.cmd stop / restart [ユーザー名]` | 停止 / 再起動 (省略すると全員。全員を停止するとサーバー管理ウィンドウも閉じる) |
| `jfs.cmd autostart on / off` | Windows にサインインしたときに、サーバー管理ウィンドウを開いて全員を起動する / しない |
| `jfs.cmd token <ユーザー名> -New` | アクセストークン (パスワード代わり) を再発行 |
| `jfs.cmd set <ユーザー名> -Port 23456` | ポートを固定の番号に変更 (`-AllowFrom` で接続を許可する相手も変更可) |
| `jfs.cmd logs <ユーザー名> [-Follow]` | 実行コマンドの記録とサーバーのログを表示 (`jfs.cmd logs monitor` でリソースモニターのログ) |
| `jfs.cmd version` | バージョン (git のコミット) を表示 |
| `uninstall.cmd` | Windows に加えた変更をすべて元に戻す (後述の「アンインストール」) |
| `jfs.cmd refresh` | 全ユーザーの起動用ファイルなどを作り直す (更新時に setup.cmd から自動で実行) |
| `jfs.cmd upgrade [ユーザー名]` | JupyterLab 本体を更新 |
| `jfs.cmd reset-venv <ユーザー名>` | venv を作り直す (入れたパッケージを初期化) |
| `jfs.cmd remove <ユーザー名>` | 環境をフォルダ (`user\<ユーザー名>`) ごと削除。`-KeepFiles` を付けるとフォルダは残す |
| `jfs.cmd monitor [-Port 8000]` | リソースモニターを設置・更新して起動 |
| `jfs.cmd monitor-stop` | リソースモニターを停止 |
| `jfs.cmd network [-SetPrivate]` | 他の PC から接続できるように、ネットワーク・ファイアウォールの現状を確認してから設定を変更 |
| `jfs.cmd doctor [ユーザー名]` | つながらないときの診断 (問題のある箇所に [NG] を表示) |
| `jfs.cmd firewall` | ファイアウォール規則を作り直す |
| `jfs.cmd protect [-Background]` | 他フォルダへのアクセス禁止を設定 (設定済みの場所は飛ばす。`-Force` で付け直し) |
| `jfs.cmd protect -Status` | アクセス禁止の設定状況 |
| `jfs.cmd unprotect` | アクセス禁止を解除 |

## サーバー管理ウィンドウとログ

`jfs.cmd start` を実行すると、**そのウィンドウがサーバー管理ウィンドウになり** (新しいウィンドウは開きません)、
起動したユーザーのサーバーはすべてその中で動きます (タイトル: `jupyter-for-share サーバー (2 人) - 閉じると全員のサーバーが停止します`)。
サーバー管理ウィンドウが動いている間は、別のコマンドプロンプトから `jfs.cmd add` / `start <ユーザー名>` / `stop <ユーザー名>` などを実行すると、
サーバー管理ウィンドウ側で起動・停止されます (新しいウィンドウは開きません)。

```
jupyter-for-share サーバー管理ウィンドウ
このウィンドウを閉じる (または Ctrl+C) と、全ユーザーのサーバーが停止します。
----------------------------------------------------------------------
[alice] [jupyter-for-share] 起動します (ポート 23456 / ログ: E:\jupyter-for-share\user\alice\.logs\server.log)
[bob] [jupyter-for-share] 起動します (ポート 27811 / ログ: E:\jupyter-for-share\user\bob\.logs\server.log)
[alice] [I 2026-10-22 12:00:00 ServerApp] Jupyter Server 2.x is running at: ...
[alice] [コマンド] 2026-10-22 12:03:10 [terminal] pip install numpy
[bob] [コマンド] 2026-10-22 12:05:42 [analysis.ipynb] df = pd.read_csv("data.csv")
```

- **ウィンドウを閉じる・Ctrl+C を押す・`jfs.cmd stop`** のどれでも、全員の JupyterLab・カーネル・ターミナルが停止します
  (×ボタンで閉じた場合は、20 秒ほどで停止します)。1 人だけ止めるときは `jfs.cmd stop <ユーザー名>` を使います。
- サーバーが異常終了したときは、ウィンドウに理由を表示して 10 秒後に自動で再起動します。
- 管理者が Windows からサインアウトするとウィンドウも閉じるため、サーバーは停止します。
  PC の再起動後は `jfs.cmd start` で開き直すか、`jfs.cmd autostart on` でサインイン時に自動で開くようにしてください。

ログは各ユーザーのフォルダの `.logs` に保存されます (JupyterLab の画面からは見えない場所です)。

| ファイル | 内容 |
| --- | --- |
| `user\<ユーザー名>\.logs\server.log` | JupyterLab の出力 (10 MB を超えると `server.log.1` に切り替え) |
| `user\<ユーザー名>\.logs\commands.log` | 本人が実行したコマンド。ターミナル (PowerShell) で入力したコマンドと、ノートブックで実行したセル (`!コマンド` や `%pip` を含む) を、日時とノートブック名付きで記録 |

※ 記録は利用者自身の権限で書き込まれるため、利用者がその気になれば書き換えや回避ができます。
操作の確認用の記録としてお使いください (改ざんできない監査ログではありません)。

## 別の PC から接続する

`jfs.cmd url` で表示される URL をブラウザで開きます。

```
http://jupyter.home.arpa:23456/lab?token=xxxx   ← setup で -Domain を指定した場合
http://jupyter-pc:23456/lab?token=xxxx          ← コンピューター名
http://jupyter-pc.local:23456/lab?token=xxxx    ← mDNS (Mac / iPhone / Linux など)
http://192.168.1.10:23456/lab?token=xxxx        ← IP アドレス
```

一度開くとブラウザに記憶されるので、2 回目以降は `http://jupyter-pc:23456/` だけで入れます。
トークンはパスワードと同じなので、本人以外に知られないようにしてください。

各ユーザーの `work` フォルダには、本人向けの短い `README.md` (自分の環境とリソースモニターのアドレス、使い方) が自動で作られます。
JupyterLab を開くとファイル一覧に表示されます。

## リソースモニター

`http://<サーバー>:8000/` をブラウザで開くと、次の情報が 2 秒ごとに更新されます (トークンは不要です)。

- CPU 使用率 (全体・コアごと・直近 5 分のグラフ)
- メモリ使用量
- GPU 使用率・GPU メモリ・温度・消費電力 (NVIDIA の場合。その他の GPU は使用率と使用メモリ)
- ユーザー環境のフォルダがあるディスクの使用量
- 各ユーザー環境の稼働状況とリンク

モニターも専用アカウント (`jfsmon`) で動き、他のフォルダにはアクセスできません。
モニターは **`jfs.cmd start` のサーバー管理ウィンドウの中で**ユーザーのサーバーと一緒に動き、ウィンドウを閉じると停止します (PC の起動時に勝手に動くことはありません)。

## 他の PC からつながらないとき (jfs.cmd network)

サーバー PC 自身や Tailscale 経由ではつながるのに、同じ LAN の別の PC からつながらない (ping も通らない) 場合は、
多くの場合 LAN の接続が「パブリック」ネットワークになっていて、ファイアウォールが受信を止めています。
管理者として次を実行してください。

```bat
jfs.cmd network -SetPrivate
```

1. **現在の状態を表示**: ネットワーク接続ごとの種類 (パブリック / プライベート)、ファイアウォールの状態、
   各ポートの許可規則と待ち受け状況、ping・名前解決の許可、python をブロックする規則
2. **適用する変更を一覧表示**して、確認 (`y`) を求めます
3. 変更を適用し、**もう一度状態を表示**して結果を確認します

変更する内容 (必要なものだけ):

| 変更 | 内容 |
| --- | --- |
| ネットワークの種類 | `-SetPrivate` を付けた場合、「パブリック」の LAN 接続を「プライベート」に変更 (Tailscale や仮想アダプターは対象外) |
| ポートの許可 | 各ユーザー環境とリソースモニターのポートを、すべてのネットワークの種類で許可 (接続元は同じサブネットのまま) |
| ping | ICMP エコー要求 (IPv4 / IPv6) の受信を許可 |
| 名前解決 | コンピューター名でつながるよう、mDNS / LLMNR / NetBIOS 名 (UDP 5353 / 5355 / 137) の受信を許可 |
| python のブロック | 過去に「アクセスを許可しない」を選んでできた、python をブロックする規則を無効化 (削除はしない) |

`-SetPrivate` を付けない場合はネットワークの種類は変えず、規則側をパブリックでも有効にして接続できるようにします。
`-Yes` を付けると確認なしで適用します。

これでも ping が通らない場合は、PC ではなくネットワーク側 (Wi-Fi の AP アイソレーション / ゲストネットワーク、
別のサブネット、他社製セキュリティソフトのファイアウォールなど) が原因の可能性があります。

## ドメイン名でアクセスする

IP アドレスの代わりに名前でアクセスする方法は 3 つあります。

1. **コンピューター名** (設定不要): 同じ LAN の Windows PC からは `http://<コンピューター名>:<ポート>/` で通常つながります。
   分かりやすい名前にしたい場合は、サーバー PC の名前を変更します (`Rename-Computer -NewName jupyter-pc` → 再起動)。
   Mac などからは `http://jupyter-pc.local:<ポート>/` を試してください。
2. **ルーター / 社内 DNS に登録** (おすすめ): ルーターの DHCP 設定でサーバー PC の IP を固定し、
   ルーターや DNS サーバーに `jupyter.home.arpa → 192.168.1.10` のような名前を登録します。
   そのうえで `setup.cmd -Domain jupyter.home.arpa` を実行すると、URL がその名前で表示されます。
3. **接続する PC の hosts ファイルに登録**: DNS を触れない場合は、接続する Windows PC で次を実行します (管理者権限)。

   ```bat
   powershell -ExecutionPolicy Bypass -File scripts\client-add-hosts.ps1 -Domain jupyter.home.arpa -ServerIp 192.168.1.10
   ```

   Mac / Linux では `/etc/hosts` に `192.168.1.10 jupyter.home.arpa` を追記します。

ドメイン名は `home.arpa` (家庭内 LAN 用に予約された名前) や社内のドメインを使うのが安全です。
`.local` は mDNS と衝突するので避けてください。

## パッケージのインストールと git

JupyterLab のターミナルを開くと PowerShell が `work` フォルダで起動し、`python` / `pip` はそのユーザーの venv を指しています。

```powershell
pip install numpy pandas          # venv にインストールされ、ノートブックからすぐ使える
pip install -r requirements.txt
git clone https://github.com/xxx/yyy.git
```

ノートブックの中では `%pip install パッケージ名` が使えます。インストール後はカーネルを再起動してください。

別の venv を追加で作ってカーネルとして使うこともできます。

```powershell
python -m venv .venv-exp          # 例: work 内に別の venv を作成
.\.venv-exp\Scripts\python -m pip install ipykernel
.\.venv-exp\Scripts\python -m ipykernel install --user --name exp --display-name "Python (exp)"
```

※ Python 本体のバージョンはサーバー PC にインストールされたもの (既定 3.12) になります。
※ git の HTTPS 認証は、ターミナル内でユーザー名と個人アクセストークンを入力する形になります。

## アクセス制限について

| 対象 | サーバー実行用アカウント (jfs-xxx) からのアクセス |
| --- | --- |
| 自分の環境のフォルダ (`work`, `venv` など) | 読み書きできる |
| 自分の `.server\jupyterlab`, `.server\config` (JupyterLab 本体・設定) | 読み取りのみ |
| 他のユーザーの環境、このリポジトリのスクリプト・設定ファイル | できない |
| 他の Windows ユーザーのプロファイル (`C:\Users\<名前>`、デスクトップ・ドキュメントなど) | できない (Windows の既定) |
| リポジトリも Windows もないドライブ (D:\ など)、リポジトリと同じドライブにある他のフォルダ、`C:\` 直下の独自フォルダ、`C:\Users\Public` | できない (`jfs.cmd protect` で拒否を設定) |
| `C:\Windows`, `C:\Program Files` など OS・アプリ | 読み取りのみ (Python・Git を動かすために必要) |
| インターネット・LAN | 使える (pip / git のため) |

- 禁止するフォルダは `servers.json` の `defaults.protectedPaths` で変更できます。`"auto"` は上の表の自動選択で、
  `["auto", "C:\\data"]` のようにパスを追加できます。変更したら `jfs.cmd protect` を実行してください。
  (後から作ったドライブやフォルダも `jfs.cmd protect` を再実行すると対象になります)
- 対象はリポジトリの場所に合わせて決まります。例えばリポジトリが `E:\tools\jupyter-for-share` にある場合、
  `E:\` や `E:\tools` そのものには拒否を付けず (付けるとサーバーが正しく動かないため)、
  `E:\` 直下の他のフォルダ・ファイルと `E:\tools` の中の他のフォルダ・ファイルに拒否を付けます。
  旧バージョンでリポジトリのあるドライブ全体 (`E:\` など) に付けた拒否は、`jfs.cmd protect` (setup でも実行) で自動的に外します。
- **処理時間について**: Windows のアクセス権 (NTFS) は、フォルダに付けた設定が中のファイル 1 つ 1 つにコピーされる仕組みのため、
  初回はドライブ内のファイル数に比例して時間がかかります。次の工夫で待ち時間を減らしています。
  - ドライブを直下のフォルダごとに分けて、最大 8 か所を同時に処理します
  - 2 回目以降は、設定済みの場所を飛ばします (新しく作られたファイルには自動で引き継がれるので付け直し不要)。
    後からドライブ直下に作られたフォルダだけが新しく処理され、サーバー管理ウィンドウを開いたときに未設定の場所があれば知らせます
  - さらに速くしたい場合は、`servers.json` の `defaults.protectLevel` を `"folders"` にすると、フォルダにだけ拒否を付けます
    (ファイル 1 つ 1 つには付けないので大幅に速くなります)。ただしこの場合、ファイルの正確なパスを知っていれば読めてしまうため、
    守りは弱くなります。既定は `"full"` (ファイルにも付ける) です
  - 処理はすべて実行したウィンドウの中で行い、終わるまで進み具合を表示します (バックグラウンドでは動きません)
- 「許可した場所以外をすべて禁止する」方式 (ホワイトリスト) も検討しましたが、Windows では
  サーバー実行用アカウントが「Authenticated Users」などの標準グループに必ず含まれ、多くのフォルダがそのグループに読み取りを許可しているため、
  アクセス権だけで実現するには結局それらのフォルダ側に拒否を付ける必要があり、速くなりません。
  (AppContainer などのサンドボックスを使えば可能ですが、Python・pip・git・ターミナルの動作に制約が出るため採用していません)
- 通信は HTTP (暗号化なし) です。信頼できる LAN 内で使い、インターネットには公開しないでください。
  ファイアウォールは既定で同じサブネット (`LocalSubnet`) からの接続だけを許可します。
- セットアップ後、このリポジトリのフォルダは管理者と setup を実行したユーザーだけが読み書きできます。サーバー実行用アカウントからは見えません。

## 設定ファイル (servers.json)

`setup.cmd` で `servers.example.json` からコピーされます。トークンが含まれるので共有しないでください (`.gitignore` 済み)。

| キー | 既定値 | 内容 |
| --- | --- | --- |
| `defaults.instancesRoot` | (空 = このリポジトリの `user`) | ユーザー環境を作る場所 |
| `defaults.python` | (自動検出) | 使う Python (全ユーザー向けにインストールされたもの) |
| `defaults.domain` | (なし) | URL に表示するドメイン名 |
| `defaults.portRange` | `[20000, 29999]` | ユーザー環境のポートをランダムに選ぶ範囲 |
| `defaults.bindAddress` | `0.0.0.0` | 待ち受けるアドレス |
| `defaults.allowFrom` | `["LocalSubnet"]` | ファイアウォールで接続を許可する相手 |
| `defaults.firewallProfiles` | `Any` | ファイアウォール規則を有効にするネットワークの種類 (接続元は `allowFrom` で制限) |
| `defaults.labLocale` | `ja_JP` | JupyterLab の表示言語 (`en` で英語) |
| `defaults.extraServerPackages` | `[]` | JupyterLab 側に追加する拡張機能など (例: `"jupyterlab-git"`) |
| `defaults.venvPackages` | `[]` | 新しく作る venv に最初から入れるパッケージ |
| `defaults.protectedPaths` | `["auto"]` | アクセスを禁止するフォルダ |
| `defaults.protectLevel` | `full` | `full`: フォルダとファイルに拒否を付ける / `folders`: フォルダだけ (速いが弱い) |
| `monitor.port` | `8000` | リソースモニターのポート (`jfs.cmd monitor -Port` で変更) |

## 処理の進め方 (バックグラウンドで動くものはありません)

- `setup.cmd`・`jfs.cmd` の処理は、すべて実行したウィンドウの中で行います。管理者権限で開き直したウィンドウは、
  処理が終わると閉じます (エラーのときや、一覧・URL・ログ・診断など表示が目的のコマンドは、読めるように Enter で閉じます)。
- ユーザーのサーバーとリソースモニターは、`jfs.cmd start` を実行したウィンドウ (サーバー管理ウィンドウ) が開いている間だけ動きます。
  PC の起動時に勝手に動くことはありません (`jfs.cmd autostart on` にした場合は、サインイン時にサーバー管理ウィンドウが開きます)。
- Python・Git・venv・パッケージは、インストールする前に既に入っていないかを確認し、入っていればそれを使います
  (Python は Program Files・`C:\Python3*`・レジストリ・py ランチャー・PATH から、全ユーザー向けで 3.9 以上のものを探します。
  ユーザー個人のフォルダにある Python は、サーバー実行用アカウントから使えないため使いません)。

## アンインストール

`uninstall.cmd` を実行すると (管理者権限の確認が出ます)、jupyter-for-share が Windows に加えた変更を**記録に頼らず探して**すべて元に戻します。
以前のバージョンが変更したまま残っているもの (ドライブ直下などに付けたアクセス禁止など) もまとめて片付けます。

1. サーバー・リソースモニターの停止 (実行用アカウントのプロセスや、このフォルダから動いているプログラムを終了)
2. 自動起動タスク (`\jupyter-for-share\`) とファイアウォール規則の削除
3. アクセス禁止 (拒否) の解除 (全ドライブの直下・その中、このフォルダの上の階層、`C:\Users\Public` を確認)
4. 実行用アカウント (`jfs-*`, `jfsmon`) とグループ、ログオン権限の削除
5. このフォルダのアクセス権を元に戻す (所有者を Administrators にし、親フォルダからの継承に戻す)
6. 実行時のファイルの削除 (`servers.json` は `servers.json.uninstalled` として残す)
7. ユーザーのフォルダ (`user\`) は残します。`uninstall.cmd -DeleteFiles` で削除します

完了後、このウィンドウと、このフォルダを開いているエクスプローラーやコマンドプロンプトを閉じれば、フォルダを削除できます。
もう一度使う場合は `setup.cmd` を実行してください (きれいな状態からセットアップし直せます)。

## トラブルシューティング

別の PC からだけつながらない場合は、まず上の「他の PC からつながらないとき」の `jfs.cmd network` を実行してください。
それ以外は `jfs.cmd doctor` を実行してください。アカウント・起動用タスク・サーバー管理ウィンドウ・待ち受けポート・このPCからの HTTP 応答・
ファイアウォール・ネットワークの種類・ログを確認し、問題のある箇所に `[NG]` と原因を表示します
(`jfs.cmd doctor <ユーザー名>` で 1 人分だけ)。

- **以前のバージョンで作成に失敗した / 一覧に出ない**: 以前のバージョンには、Windows PowerShell 5.1 で設定ファイル
  (`servers.json`) の一覧部分が壊れる不具合がありました。最新版では読み込み時に自動で修復します (修復前のファイルは `servers.json.bak`)。
  - `jfs.cmd list` で状態が「起動用タスク未登録」のユーザーは、`jfs.cmd refresh` で登録し直せます
  - 作成途中のフォルダやアカウントが残っていて作成できない場合は、`jfs.cmd remove <ユーザー名>` で片付けてから作り直してください

- **別の PC からつながらない**
  - `jfs.cmd list` で「起動中」になっているか確認。なっていなければサーバー管理ウィンドウの表示か `jfs.cmd logs <ユーザー名>` でエラーを確認
  - サーバー PC のネットワークが「パブリック」になっていないか (setup が警告を出します)。「プライベート」に変更してください
  - 接続元が別のサブネットの場合は `jfs.cmd set <ユーザー名> -AllowFrom 192.168.0.0/16` のように許可範囲を広げる
  - サーバー PC 上のブラウザで `http://localhost:<ポート>/` が開けるか確認
- **コンピューター名でつながらない**: IP アドレスの URL を使うか、「ドメイン名でアクセスする」の 2 か 3 を設定してください
- **GPU が表示されない**: NVIDIA の場合はドライバが入っているか (`nvidia-smi` が動くか) を確認してください。`jfs.cmd logs monitor` にエラーが出ていないかも確認できます
- **PC のスリープでつながらなくなる**: `setup.cmd -DisableSleep` で AC 電源時のスリープを無効にできます
- **ターミナルでスクリプト (Activate.ps1 など) が実行できない**: 実行ポリシーは RemoteSigned に設定済みです。
  インターネットから取得したスクリプトはブロックされることがあるので `Unblock-File` を使ってください
- **アクセス禁止の設定が終わったか知りたい**: `jfs.cmd protect -Status` で、実行中かどうか・設定済みの場所・ログの末尾が表示されます
- **フォルダを削除できない / 以前の設定が残っていないか心配 / 全部やり直したい**: 「アンインストール」の節を参照してください
- **使っているバージョンを確認したい**: `jfs.cmd version`。`setup.cmd` は最初に `git pull` で更新しますが、
  失敗した場合は古いままになります (失敗したときは画面にメッセージを表示して止まります)
- **起動時に PermissionError が出る**: `jfs.cmd doctor <ユーザー名>` を実行すると、そのユーザーの実行用アカウントとして
  ドライブ直下から作業フォルダまでの各場所を読めるかをテストし、読めない場所 (NG) とそのアクセス権を表示します
